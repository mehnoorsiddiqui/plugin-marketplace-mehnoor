# Maxio SDK Assistant (Claude Code plugin)

A Claude Code plugin that helps developers **install and consume the Maxio Advanced Billing
(Chargify) Python SDK**, plus reusable guidance for working with **any APIMatic-generated Python
SDK**.

Skills only — no agents, no MCP server, no telemetry.

## The SDK map

The `python-getting-started` skill bundles a generated table of contents for the SDK, so no clone is
needed to answer a contract question:

```
skills/python-getting-started/
  SKILL.md
  sdk-map.md            client construction, error model, controller index, models, servers & auth
  map/operations/       34 pages — one per controller, 250 operations
```

Each operation block carries its HTTP verb and route, the exact sync parsed signature, parameter
roles and wire names where they differ, both return types, its error case, **its server**, and a
**Type sources** table naming the module that declares every type it mentions.

The map is the **locator**; the installed package is the **ground truth**. Locating something by
grep, glob or find over the SDK tree is a defect — open the map index and follow the link, then open
only the one module a row names.

## Two layers

The Maxio SDK is generated by the [APIMatic](https://www.apimatic.io/) code generator, which emits
the same cross-cutting shape for every Python SDK it produces. The plugin reflects that:

| Layer | Skill(s) | Names used |
| --- | --- | --- |
| **SDK-specific** (entry point) | `python-integrate-maxio`, `python-getting-started` (+ the bundled SDK map) | Concrete Maxio names (`MaxioAdvancedBillingClient`, `maxio_advanced_billing`) |
| **API-agnostic usage** | `python-integration-planning`, `python-client-initialization`, `python-authentication`, `python-calling-endpoints`, `python-models`, `python-error-handling`, `python-configuration-resilience`, `python-inbound-state`, `python-sdk-drift`, `python-testing` | Placeholders (`{Api}Client`, `{group}`, …) so they apply to *any* APIMatic Python SDK |

The agnostic skills never name Maxio — they describe the generator's patterns, so they apply to
whatever APIMatic Python SDK your project consumes. Where an SDK map is bundled (as it is here), they
defer to it for lookup before touching the SDK source.

## Skills

- **python-integrate-maxio** — the router. Plan-first: a hard gate on `maxio-plan.md` carrying a
  contract sheet with no open lookups before any project file is created or edited, then a
  step-by-step workflow naming the companion that governs each step.
- **python-getting-started** — SDK identity, install, the bundled map, the three servers and their
  URL template variables, the two auth schemes, and the error model. Start here.
- **python-integration-planning** — the seven readiness questions a plan must answer. Load before any
  architecture decision; rows D (inbound state) and F (change safety) are the two that get skipped,
  because nothing in the code looks wrong without them.
- **python-client-initialization** — construction, the keyword-only boundary, lifetime and teardown,
  sync vs async.
- **python-authentication** — supplying credentials, and refusing to boot without them.
- **python-calling-endpoints** — the call surface and its two response modes.
- **python-models** — payloads, `UNSET` vs `None`, wire aliases, input companions, open enums.
- **python-error-handling** — the failure families, and what each means for the caller.
- **python-configuration-resilience** — timeouts, the retries you build yourself, bounded paging.
- **python-inbound-state** — webhooks, replays, out-of-order delivery, settling an unanswered write.
- **python-sdk-drift** — pinning the SDK and holding the runtime behaviour its types do not express.
- **python-testing** — the transport seam, and what counts as proof.

## What this SDK does not give you

Three things the skills call out because the signatures hide them:

- **No retries.** `core/raw_client.py` cites ADR-0001 ruling them out. Any retry is yours to build.
- **No paginator.** `page` / `per_page` are ordinary parameters; a page loop is hand-written and
  needs a cap that does not depend on the provider's cooperation.
- **No credential validation.** `basic_auth` and `bearer_auth` both default to `None`, which installs
  `no_auth` — requests then go out unauthenticated and return `401`, with nothing failing at
  construction.

And one that costs you production: the base URLs carry `{site}` / `{connector}` template variables
whose defaults are the literals `"subdomain"` and `"connector"`. Leave them unset and every call goes
to a host that is not yours.

## Install

```
/plugin marketplace add apimatic/plugin-marketplace
/plugin install maxio-sdk@apimatic
```

Then ask a usage question (e.g. *"how do I authenticate this SDK with an API key?"*) to trigger the
relevant skill.
